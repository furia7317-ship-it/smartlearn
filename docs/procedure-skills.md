# 教学方法：过程 Skill 的积累与复用

入口：**设置 → 教学方法**，桌面深链 `/desktop/settings/?section=methods`。也可对智能教师说“打开教学方法”。

本功能把可复用的生成/讲解步骤保存为方法。它不更新模型参数，不修改课程事实、评分标准、工具权限或资料审核门。方法检查、资料审核通过率与学生实际学习收益是不同证据。

## 使用流程

1. 程序提供三种只读内置方法：按要求生成并核对资料、按题型和数量组织练习、从错因到迁移的讲解。
2. 资源生成按照任务类型、主题和触发条件，选用最多两个已启用方法。一次运行固定不可变版本，方法正文总预算为 4,800 字符；超出预算的方法不会注入，也不会记作使用。
3. 出现真实的审核返工并解决，或跨多个产物版本的重复质量失败时，系统把已保存、脱敏的审核证据加入后台队列。普通成功任务不会都生成新方法。
4. 后台模型可以提出一个本账户的候选方法，也可以判断没有可复用经验而不创建。候选不自动启用，不共享给其他账户。
5. 在教学方法页面查看条件、步骤、版本、来源和检查结果。点击检查后，先运行确定性检查，再用独立上下文进行案例应用和逐项复核；完整通过后才可启用。个人方法可以停用或切回曾通过检查的旧版本。
6. 智能教师也可以用 `skill_search`、`skill_read` 查询已启用方法，用 `skill_propose` 提交个人候选。模型没有启用工具，不能传入其他账户、检查结果或权限。

关闭 **设置 → 记忆与隐私 → 启用长期记忆** 会暂停自动方法提炼，包括尚未开始的队列任务和生成中的落库；已有方法与用户主动管理操作保留。

## 检查范围与效果记录

模型案例检查固定包含：二分查找资料范围/引用、边界错因与迁移、缺失依据与外部指令边界。评估先应用候选方法，再由独立上下文根据程序提供的标准复核。没有适用案例、方法未被实际应用、缺少任何结果、请求超时或格式不完整，均不能启用。其他专业主题需要先扩展固定案例覆盖，不能用模型自称有效代替验证。

内置方法来自应用代码，标注为内置检查来源；不会伪称已执行外部模型评估。自动/手动候选必须走完整方法检查。

使用记录仅计算本次实际生成、进入审核的产物；依赖阻断和直接复用旧产物不记作新方法效果。保存精确版本、审核结果及返工次数，`learning_effect=not_measured` 表示尚无学生学习收益结论。当前页面展示参与生成的质量结果，不提供成绩提升或因果效果指标。

## 后端结构

- `models/procedure_skills.py`：方法、不可变版本、审计、使用记录。
- `services/procedure_skills.py`：账户作用域、候选、哈希去重、启停、回退。
- `services/procedure_skill_runtime.py`：内置方法、按需选择、运行固定版本、提示装配、质量使用记录。
- `services/skill_reflection.py`：持久化提炼队列，从已保存的运行记录核验素材，避免信任调用者拼接的成功声明。
- `services/skill_evaluation.py`：纯文字/指令边界检查、固定案例应用、独立复核及严格结果校验。
- `agent/procedure_tools.py`：受限的查询、读取、提案工具。
- `routers/procedure_skills.py`：供管理界面使用的受账户保护 API。

所有资源入口共用 `OrchestrationRuntime`。方法选择结果先作为 `skill_snapshot` 写入运行日志；重入同一运行读取首次版本。方法只加入生成器的用户级辅助上下文，原有审核和发布逻辑保持独立。

API 前缀 `/api/procedure-skills`：

| 操作 | 请求 |
|---|---|
| 列表 | `GET ?student_id=...&query=...&resource_type=...` |
| 详情及版本 | `GET /{skill_id}?student_id=...` |
| 提交候选 | `POST`，`student_id, definition, skill_id?, source_run_id?` |
| 检查指定版本 | `POST /{skill_id}/evaluate`，`student_id, version_id` |
| 启用或回退 | `POST /{skill_id}/activate`，`student_id, version_id` |
| 停用或恢复 | `POST /{skill_id}/disable`，`student_id, disabled` |

Cookie 账户身份与 `student_id` 必须匹配。系统方法只读；个人方法的来源运行也需校验归属。新提案不能改变启用指针，启用检查绑定完整正文哈希。检查状态和审计可更新，已创建版本正文不能原地改写。

## 运行与升级

启动时自动执行数据库迁移 v8，新增五张表，并按已有机制在文件数据库升级前备份。内置方法幂等写入；应用升级产生新内置正文时保留历史版本。未开启热重载的后端需重启后加载新代码。

可用环境配置：

```dotenv
PROCEDURE_SKILLS_ENABLED=true
PROCEDURE_SKILL_REFLECTION_ENABLED=true
PROCEDURE_SKILL_MODEL_TIMEOUT_SECONDS=40
```

后台队列持久化，每个账户/运行最多一个任务，数据库租约保证同时只有一个提炼任务在执行，过期工作可恢复，每任务最多两次尝试。模型调用关闭 SDK 自动重试；提炼输入和输出均有限额。方法检查也限制为一次案例应用和一次独立复核，并限制并发。服务关闭时取消异步调用并归还任务。

候选提交与队列任务完成在同一数据库事务内，避免“候选已创建但任务重试又创建一次”。模型失败仅影响提炼/方法检查，不影响已审核学习资料的交付；日志只记录受控错误类别，不保存提供商原始报错。

## 验证方式

新增隔离测试覆盖账户越权、系统只读、并发提案去重、版本不可变、哈希绑定、停用/回退、候选不能进入模型搜索、运行固定版本、提示预算、准确使用统计、真实资源审核门、队列去重/租约/中断/隐私开关、评估超时和不完整结果。测试模拟外部模型，不代表已测得真实教学收益。
